Required content:

H3: Python for AI

You already know a language; the gap is idioms, not syntax: typing, dataclasses and pydantic, virtual environments and packaging, async clients, notebooks vs scripts, and above all NumPy and pandas fluency. Band: 3–4 weeks to fluency for a working developer, in parallel with everything else. "Enough" means writing, structuring, debugging and profiling a data-handling script without looking up the basics.

H3: Statistics & Maths — The Honest Scope

Probability and distributions, mean and variance, conditional probability and Bayes intuition, basic linear algebra (vectors, dot products, matrices — because embeddings and attention are dot products), derivatives and gradient intuition, and the ability to read a loss curve. Not proofs, not measure theory. Band: 4–6 weeks, in parallel with building. State plainly that applied-role interviews test intuition rather than derivations, and that fear of maths is the single most common reason developers delay a transition they could have made.

H3: Machine Learning Fundamentals

Supervised vs unsupervised learning, train/validation/test discipline, overfitting and regularisation, metrics (precision, recall, F1, ROC-AUC, MAE/RMSE), feature engineering basics, cross-validation, and when classical ML beats an LLM (tabular data, low latency, low cost, explainability). scikit-learn as the tool. Band: 5–8 weeks. Interview reality: conceptual questions and "which metric, and why".

H3: Deep Learning Basics

Tensors, a training loop in PyTorch, loss and optimiser, what a network actually learns, CNN/RNN at intuition level, what a transformer is and why attention matters. Band: 3–5 weeks. Building a transformer from scratch is optional understanding, not a hiring requirement for applied roles — say so.

H3: GenAI, LLM Mechanics and Modern NLP

Tokenisation, embeddings (numerical representations of meaning), attention (intuition → visual → code), context windows, temperature and top-p, inference cost and latency drivers, why hallucination happens, model families (proprietary vs open-weight). Cover NLP as it exists now: the tasks that survived the transformer shift — classification, NER, summarisation, extraction, semantic similarity — are mostly done with transformer models and LLMs; hand-built TF-IDF pipelines and classic parsers are largely legacy for applied roles, but remain worth knowing as cheap baselines. "Explain an embedding to a product manager" is a standard interview question.

H3: AI APIs, Structured Outputs and Data Handling

OpenAI, Anthropic and Google Gemini APIs; open-weight models via Hugging Face and Ollama; structured outputs and schema enforcement; function calling; streaming; retries and idempotency; prompt versioning. This is the developer's home turf — say it takes days, not weeks. Then the part developers underestimate: data handling and quality — parsing messy JSON, PDF and HTML; chunking documents; deduplication; labelling a small golden set; data leakage; PII scrubbing. This decides RAG quality more than the model does.

H3: Embeddings, Vector Databases and RAG

Embedding models and their trade-offs; pgvector (the reader's Postgres advantage), ChromaDB, Pinecone, Weaviate; indexes (HNSW/IVF at intuition level); similarity metrics; metadata filtering; hybrid search with BM25. Then RAG — defined once — from basic to production: chunking strategies, retrieval quality, hybrid search, re-ranking, query rewriting and decomposition, citation and grounding, retrieval and answer evaluation, latency and cost optimisation, failure analysis. The single most-requested competency in 2026 Indian GenAI JDs (author's JD analysis). System-design question to expect: document Q&A over 10 million documents.

H3: Agents and MCP

Tool use, ReAct and planning patterns, memory, loop and cost control, error recovery; multi-agent orchestration (supervisor and delegation patterns); frameworks — LangGraph, CrewAI, AutoGen, OpenAI Agents SDK — and when to use which; MCP, defined once as an open standard for connecting models to tools and data sources, including building and consuming MCP servers. Fastest-growing JD area and the most natural fit for API-fluent developers.

H3: Fine-Tuning and Model Adaptation

The decision framework (prompt vs RAG vs fine-tune vs train) matters more than the technique. Dataset construction, SFT, LoRA/QLoRA (parameter-efficient fine-tuning — defined once), evaluation against the base model, deployment of the tuned model. Interviewers ask "when would you fine-tune?" far more often than "implement LoRA".

H3: Evaluation and Guardrails

Golden datasets, automated evaluation pipelines, LLM-as-judge and its limits, regression testing for prompts, hallucination detection, prompt-injection and jailbreak defence, PII handling, bias and fairness, and compliance context for Indian BFSI and healthcare deployments. The area that most separates hired from rejected developers — say so.

H3: MLOps, Deployment, Cloud and Cost Engineering

The reader is most of the way there: containerised FastAPI serving and CI/CD transfer directly. Add model and prompt versioning, evaluation in CI, monitoring for quality (not just uptime), drift and cost tracking, secret management, inference and GPU basics, and open-weight serving (vLLM / Ollama at awareness level). Cloud: pick one and learn its AI layer — AWS Bedrock/SageMaker, GCP Vertex AI, Azure OpenAI / AI Foundry — plus managed vector search and cost controls; enterprise and GCC JDs name these explicitly. Cost and latency: token accounting, caching, batching, model routing (small vs large models), streaming for perceived latency, quantisation at awareness level. Full stack performance instincts transfer almost unchanged.

H3: What Courses and Roadmaps Oversell to Developers (200–300 words)

Prompt engineering as a career · six months of classical ML for a GenAI target · deep learning theory from first principles · building transformers from scratch as a hiring signal · Tableau/Power BI inside an "AI" program · DSA-heavy bootcamps for someone already employed as an engineer · "learn twelve frameworks" when the JD names two or three.

3. LLM mechanics: tokens, embeddings, attention, cost — so you can explain what you just shipped
